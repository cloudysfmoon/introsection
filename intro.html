The lab

Hands-on network lab work from WGU's Network Analytics & Troubleshooting coursework — a GNS3 lab environment running VyOS routers, OPNsense, and Windows Server, with six help desk tickets to diagnose and close out.

TKT-01closed

Unauthorized FTP service on DMZ-Server2

found
Service enumeration on the DMZ segment turned up an active vsftpd daemon on DMZ-Server2 — a host with no legitimate reason to expose file transfer to that zone.
fix
Disabled and removed the FTP service, then logged the finding as an unauthorized-service ticket.

TKT-02closed

DNS cache poisoning on a Windows Server 2016 DNS host

found
A malicious wgu.edu zone had been injected into the DNS role — records that didn't match the expected baseline and could redirect legitimate traffic to an attacker-controlled host.
fix
Removed the poisoned zone records and tightened zone transfer settings to close the path the injection came through.
DNS securityzone transfer hardeningWindows Server
TKT-03closed

Routing loop on Router4

found
Traffic to a downstream subnet was looping between routers and exhausting TTL instead of reaching its destination.
fix
Traced the path hop by hop, isolated the conflicting entry in Router4's routing table, and corrected it to restore a single stable path.
routing table analysistroubleshooting methodology
TKT-04closed

DHCP/DNS misconfiguration on Router1

found
Clients on USER-Net (10.10.40.0/24) were failing to lease IP addresses and couldn't resolve hostnames.

found
